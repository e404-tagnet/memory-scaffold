# SKILL: SOP Builder
> Run this when creating any new standard operating procedure or process document.

---

## When to activate
- User asks to document a process or workflow
- User wants a checklist for a recurring task
- User is onboarding someone and needs written steps

---

## SOP structure (always use this)

Every SOP must include:

**Header**
- Process name
- Owner (role, not name)
- Frequency (daily / weekly / per event)
- Last reviewed date
- Trigger (what starts this process?)

**Steps**
- Numbered, not bulleted
- Each step: one action, one owner, clear definition of "done"
- Maximum 15 steps — if more, break into sub-processes

**Definition of done**
- What does completion look like?
- Is there an output, a confirmation, or a handoff?

**Failure modes**
- What are the top 2-3 ways this process goes wrong?
- What should the owner do if it breaks?

---

## Key person risk flag
If any step can only be done by one specific person (not just their role), flag it:

> ⚠️ **Key person risk:** Step X currently relies on [person's name]. Document their knowledge or cross-train before this becomes critical.

---

## Output format

```
## [Process Name]

**Owner:** [Role]
**Frequency:** [When]
**Trigger:** [What kicks this off]
**Last reviewed:** [Date]

### Steps
1. [Action] — Owner: [Role] — Done when: [Criterion]
2. ...

### Definition of done
[What the completed process looks like]

### If it breaks
- [Failure mode 1]: [What to do]
- [Failure mode 2]: [What to do]

**Review this process every [X weeks/months].**
```
